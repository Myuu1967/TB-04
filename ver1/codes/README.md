# ver1 サンプルプログラム

自作 4bit CPU **TB-04 ver1**（データ4bit／アドレス4bit／16命令）で実機動作させたプログラム集です。

各プログラムは `.ASM`（ソース）と `.bin` / `.hex`（アセンブル済みROMイメージ）の3点セットで置いてあります。`.hex` は Intel HEX 形式で、そのまま 28C256 に焼けます。

## ver1 の制約

このCPUの制約を知っていると、コードの書き方の理由が見えてきます。

- **プログラムROMは16語**（PCが4bit）。つまり **1本あたり最大16命令**。ほとんどのデモが「ちょうど16命令」で収まっているのはそのためです
- **汎用レジスタは R0〜R3 の4本**だけ。即値は4bit（0〜15）
- **フラグ保持の機構がない**（C・Z は EXE フェーズで無条件ラッチされ、`MOV`/`MOVI`/`OUT`/`OUTI` は C,Z を0クリアしてしまう）
  → **フラグを立てる命令（`ADD`/`SUB`/`ADDI`/`SUBI`/`AND`/`OR`/`XOR`、`IN` の Z）の直後に分岐命令（`JNC`/`JZ`）を置く**のがver1の運用規約です。退避や表示は分岐より後に回します
- 4bit演算なので加減算はすべて **mod 16**。この「あふれ」を仕様として利用しているデモがいくつかあります

## アセンブルのしかた

```
cd ver1/tools
python tanuki_asm.py    ../codes/counter.asm    -o ../codes/counter      # 16語・単一ページ
python tanuki_asm256.py ../codes/MIXED_CORD.ASM -o ../codes/MIXED_CORD   # 256語・マルチページ
```

`.bin` と `.hex` が生成されます（`--no-bin` で抑止）。通常は `tanuki_asm.py` を使い、後述の `MIXED_CORD` だけ 256語版を使います。

## デモプログラム

| ファイル | 内容 | 出力 |
|---|---|---|
| [`LED_FLOW.ASM`](LED_FLOW.ASM) | 流れるLED | IN=0: `1,3,6,12,8,12,6,3`（8周期・往復）／IN≠0: `3,6,12,8`（4周期・一方向） |
| [`counter.asm`](counter.asm) | カウントアップ／ダウン | IN=0: `15→0` ダウン／IN≠0: `1→15→0` アップ |
| [`FIBONACCI.ASM`](FIBONACCI.ASM) | フィボナッチ数列 mod 16 | 周期24 `1,2,3,5,8,13,5,2,7,9,0,9,9,2,11,13,8,5,13,2,15,1,0,1` |
| [`RAMEN_TIMER.ASM`](RAMEN_TIMER.ASM) | ラーメンタイマー（TD4オマージュ） | `1`→`3`→`0,7` 点滅×16→`15` で停止 |
| [`KAKEZAN_44.ASM`](KAKEZAN_44.ASM) | かけ算 四四（4×4の全16積） | `1,2,3,4／2,4,6,8／3,6,9,12／4,8,12,0` で停止 |
| [`LIFE_CA.ASM`](LIFE_CA.ASM) | 1次元セルオートマトン | 周期15 `1,2,4,8,3,6,12,11,5,10,7,14,15,13,9` |
| [`PRED_PREY.ASM`](PRED_PREY.ASM) | 捕食者と被食者の個体数振動 | 周期6 (被食,捕食)=`(15,8)(15,15)(8,15)(1,8)(1,1)(8,1)` |
| [`TASHIZAN_44.ASM`](TASHIZAN_44.ASM) | 四の段を延々出力（`KAKEZAN_44` の停止なし版） | ※ `.bin`/`.hex` は未生成 |
| [`MIXED_CORD.ASM`](MIXED_CORD.ASM) | 上記7デモを1個の256語ROMに同梱（後述） | ページ切替で選択 |

### LED_FLOW — 流れるLED

`OUTI` でパターン列を直接出すだけの構成で、**シフト命令を使わずに**流れるLEDを実現しています。IN の値で往復パターンと一方向パターンを切り替えます（`IN`→`JZ` で分岐）。お披露目向きの一本。

### counter — カウントアップ／ダウン

`IN`→`JZ` で分岐し、`ADDI R0,1` を回すか `SUBI R0,1` を回すかを選びます。`IN` が Z フラグを更新することを利用した最小の分岐例です。

### FIBONACCI — フィボナッチ数列 mod 16

4bitレジスタなので自然に mod 16 になります。フィボナッチ数列を mod m で取ると必ず循環し（**ピサノ周期**）、π(16) = 24 項です。目印は「0 の次に 9 が2回続く」ところと、`15`（全点灯）。7命令/項のループで、`XOR R2,R2` をゼロクリアに使っています。

### RAMEN_TIMER — ラーメンタイマー

`ADDI R0,1` を C が立つまで回す（＝16回）ことを時間の単位に使う遅延ループです。`JNC` でループを作り、区切りごとに `OUTI` で表示を変え、最後に `15`（全点灯）を出して自己ループで停止します。

### KAKEZAN_44 — かけ算 四四

足し算の繰り返しで i×j を作ります。見どころは**レジスタ不足を「終了フラグの転用」で解決**しているところ。4×4=16 は4bitで 0 に落ちて Z=1 が立つので、これをそのまま停止条件に使い、外側ループ用のカウンタを不要にしています。おかげで R0=作業/内側カウンタ、R1=積、R2=被乗数、R3=定数4 の**4本ちょうど**で成立し、**16語ROMにちょうど16命令**で収まりました。

### LIFE_CA — “生きている”1次元セルオートマトン

4セル（=OUT の4LED）だけの素直なセルオートマトンは、線形性のせいで必ず全滅（→0000）してしまいます。そこで**あふれたビットを帰還させて自己再生させる** 4bit最大長LFSR（周期15）＝「Rule60＋帰還」にしました。種 `0001` から非ゼロ15状態を巡回し、消えません。

- 左シフト = `ADD R1,R1`（C = あふれた最上位）
- `JNC` で分岐 → C=1 のとき `XOR R1,M`（帰還タップ M=`0b0011`）
- `IN`→`AND`（マスク `0b0111`）→`OR` でセルを注入し、インタラクティブに軌道をかき乱せます

**XOR / AND / OR を全部使う**のもこのプログラムの役どころです。なお本家コンウェイのライフゲームは盤面用のRAMが要るので ver1 では不可能で、これは ver2（データメモリ導入）への動機になりました。

### PRED_PREY — 捕食者と被食者の個体数振動

本物のロトカ・ヴォルテラ方程式は `prey×pred` の積の項が要るので、乗算のない4bit・16命令では重すぎます。そこで平衡点 K=8 まわりの**線形振動子**を**シンプレクティック更新**（pred の更新に、更新後の prey' を使う）で解き、軌道が閉じる周期6の個体数サイクルにしました。**足し算と引き算だけ**で成立します。

```
prey' = prey + (K - pred)     ; 捕食者が少ないと草食が増える
pred' = pred + (prey' - K)    ; 草食が多いと肉食が増える（更新後の prey' を使う）
```

線形写像 M = [[1,-1],[1,0]] は M⁶ = I（固有値 e^{±iπ/3}）なので、mod 16 でも**厳密に周期6**になります。初期値 prey=8, pred=1 で 1〜15 をフルスイングし、草食のピークから**1世代遅れて**肉食がピークを迎える位相遅れが観察できます。条件分岐を使わない純算術＋`JMP` なので、フラグ運用規約の制約を受けません。

> 軌道は平衡点 (8,8) を通らない閉軌道です。「被食==捕食」になるループが2回（`(15,15)` と `(1,1)`）あり、そこでは LED の見た目が変わらないため止まって見えますが、実際は循環し続けています。

### MIXED_CORD — 7デモを1個のROMに同梱

上の7デモを**16語ページ境界に `.org` で並べて**、256語のROM1個にまとめたものです。

| ページ | デモ | | ページ | デモ |
|---|---|---|---|---|
| `0x00` | LED_FLOW | | `0x80` | LIFE_CA |
| `0x20` | Counter | | `0xA0` | RAMEN_TIMER |
| `0x40` | FIBONACCI | | `0xC0` | PRED_PREY |
| `0x60` | TASHIZAN_44 | | | |

**切り替えはプログラムROM（28C256）の上位ニブル A4–A7 を手動セレクタで選ぶだけ**です。PC 本体は4bitのままで、各デモは自ページ内でループし `JMP` も下位4bitで同ページ内に閉じるので、ページの外へは出ません。**CPU側の変更は不要**で、A4–A7 を選択可能にするだけで動きます（実機確認済み）。

ソフトだけでメニュー切替を作ることはできません。`JMP` が下位4bitしか書けずページを跨げないためで、ハード側のページセレクタが素直な解になります。

アセンブルには **`tanuki_asm256.py`** を使ってください（ラベルを16語ページ単位でスコープ化し、`JMP`/`JZ`/`JNC` を下位4bitで符号化、ページ跨ぎはエラーにします）。

## 命令の動作確認用

実機の立ち上げ・デバッグ時に、命令やポートを1つずつ潰していくために書いたものです。ほとんどが16語を埋める形になっています。

| ファイル | 確認内容 |
|---|---|
| `NOP.ASM` | `NOP` ×16（PCが進むことの確認） |
| `MOV.ASM` | `IN` で値を入れて R0〜R3 の全転送組み合わせ |
| `MOVI.ASM` | `MOVI 0`〜`MOVI 15`（即値16通り） |
| `ADD.ASM` | `IN` で値を入れてレジスタ間加算 |
| `ADDI.ASM` / `SUBI.ASM` | 即値 0〜15 の加算／減算（桁上げ・借りの確認） |
| `OUT_I.ASM` | `OUT` と `OUTI` の両方。`1,2,4,8,4,2,1` で単LEDが往復 |
| `JMP_N.ASM` | 全16番地への `JMP`（アドレス各ビットの確認） |
| `JNC.ASM` | `ADDI`→`JNC` のループと `SUBI`→`JZ` のループを両方通す |
| `IN_OUT.ASM` / `IN_ADD.ASM` / `IN_MOV.ASM` | IN ポートと各命令の組み合わせ |
| `IN_AND.ASM` / `IN_OR.ASM` / `IN_XOR.ASM` / `IN_SUB.ASM` | 論理演算・減算の全パターン掃引 |

`IN_AND.ASM` は実機デバッグで役に立った一本で、AND 命令の全レジスタ組み合わせを掃引しながらロジックアナライザでセレクト信号を同時観測し、**MUXの誤結線**（74HC253 の S1 と `/E2` の取り違え）を突き止めました。
